# 提示词 → 工具调用：工作流

这份文档描述本插件里「一句话/参考材料」变成 NovelAI caption 的完整链路，以及预设、工具契约、模型三种角色各自负责什么。目标是让每一步都可配置、可预览、可核对。

## 1. 端到端流程

```
用户描述 / 参考图 / 角色库 / 标签库条目
        │
        ▼
① 变量注入         {{用户描述}} {{角色库}} {{参考条目}} {{画面尺寸}}（DNA 用 {{补充说明}}）
        │
        ▼
② 预设组装         当前预设的段 → system 段合并；user/assistant 段按顺序成为消息
        │             （空段、未启用的段跳过）
        ▼
③ 模型调用         A. 提示词模式：只发 messages，模型按字段语法输出文本
                   B. 工具模式：额外发送 tools=[submit_caption] + 自动工具选择
        │
        ▼
④ 结果解析         工具模式优先读 tool call 的 arguments；
                   没有工具调用时回退解析文本（flat 字段或 JSON）
        │
        ▼
⑤ 校验与规范化     scene / scene_uc / char（≤6）；字段转成 caption 结构
        │
        ▼
⑥ 消费             面板回填工作台；nai_write_prompt 返回文本；
                   或交给 nai_generate 出图
```

## 2. 三种角色

### 2.1 预设段（指令层）

「设置 → 提示词预设」里的当前预设，由若干段组成：

| 段字段 | 作用 |
| --- | --- |
| 段名 | 只是标注，方便识别 |
| 角色 | `system` 合并进系统提示；`user` / `assistant` 按顺序进入对话 |
| 启用 | 关闭的段不参与本次写词 |
| 内容 | 支持 `{{变量}}`；空内容的段会被跳过 |

- 内置预设随插件更新、只读；点「保存」会自动另存为自定义预设。
- `assistant` 段可以用来放示例输出（few-shot），顺序就是发送顺序。
- 写词 / DNA 两类各自有「当前预设」。

### 2.2 变量（上下文注入）

| 变量 | 含义 |
| --- | --- |
| `{{用户描述}}` | 用户输入的一句话；没有时给「按参考图来」 |
| `{{角色库}}` | 被提及/勾选角色的 DNA 文本 |
| `{{参考条目}}` | 从标签库挑的条目原文 |
| `{{画面尺寸}}` | 当前宽×高 |
| `{{补充说明}}` | 仅 DNA 写词用 |

### 2.3 工具契约（输出层）

工具模式开启时，请求里会带一个真实的函数工具：

```json
{
  "name": "submit_caption",
  "description": "提交这一张 NovelAI 图的完整 caption……",
  "parameters": {
    "type": "object",
    "properties": {
      "scene":    { "type": "string", "description": "场景/构图正向标签" },
      "scene_uc": { "type": "string", "description": "全局负面标签" },
      "char":     { "type": "array",  "description": "角色列表 ≤6，含 center/positive/negative" },
      "analysis": { "type": "string", "description": "中文分析，不进入提示词" },
      "size":     { "type": "string", "description": "可选宽x高" }
    },
    "required": ["scene"]
  }
}
```

字段说明本身就是给模型的规则；工具模式下这些规则和预设段里的指令**同时**生效。模型只回工具调用、不回正文也没问题。

## 3. 两种模式怎么选

| 场景 | 建议 |
| --- | --- |
| 宿主模型支持 function calling | 开「工具调用输出」：结构化程度最高，参数直接可校验 |
| 模型/中转不支持 tools | 关掉：走字段语法文本，失败时按 `writerRetries` 重试 |
| 想要示例/风格引导 | 在预设里加 `assistant` 段放示例，工具模式与提示词模式都可用 |
| 需要确认实际发送内容 | 预设卡「预览当前预设」：显示 system、各条消息，工具模式还会显示工具 schema |

## 4. 失败与重试

| 失败 | 处理 |
| --- | --- |
| 文本不是字段格式 | 按 `writerRetries` 追加纠正消息重试 |
| 工具参数无法解析成 caption | 回退到文本解析；仍失败则格式错误 |
| 模型拒绝（内容审核） | 返回 `WRITER_REFUSED`；开启「成人向创作范围」时会额外重试一次 |
| 工具模式被模型忽略 | 自动回退解析文本里的 JSON（提示词里的工具说明仍在） |
| 结果为空/截断 | 记录 `finishKind`、`truncated`，日志可见 |

## 5. 怎么确认预设生效

1. **预览**：设置 → 提示词预设 → 「预览当前预设」，看 system、messages、tool。
2. **日志**：`write` / `dna` 条目带 `preset: { kind, id, name, builtin }`，成功摘要写「预设「X」」。
3. **接口**：`POST /write` 返回 `preset`；`nai_write_prompt` 输出末尾标注预设名。
4. 手工编辑 `presets.json` 后按 mtime 自动重载，不需要重启。

## 6. 推荐预设组合

- **单图（默认）**：内容规则(system) + 标签库用法(system) + 用户消息(user)。
- **多角色**：在用户消息里强调「角色按出场顺序、最多 6 个」，工具模式让模型填 `char` 数组。
- **风格模板**：追加一个 `assistant` 段放示例 caption，再放一个 `system` 段说明「示例只示范结构，不要照抄内容」。
- **工具优先**：预设可以精简为「内容规则」+「用户消息」，把字段规则留给工具 schema，减少重复。
